# Research access and scientific provenance

## Public boundary

The public API is an allowlisted projection; it never exposes private manuscript drafts, Workspace owner/project IDs, credentials, proprietary datasets, local source paths or unreleased figures. A public article synopsis is not permission to publish every associated object.

The initial public catalog is intentionally empty. Only metadata explicitly marked `public-approved` passes the read-only API; fields are explicitly reconstructed to prevent extras from leaking. Before real publication, approved source rights, reviewed article content and a production identity/authorization boundary require independent acceptance.

## Scientific integrity

A scientific figure must preserve source authority, input checksums, units, data classification (observed/modelled/synthetic/illustrative), renderer version, assumptions and limitations, reviewer decision, and any publication caveats. Reproducibility tests and graph connectivity do not independently validate empirical carbon removal or causal claims.

## Versioning

Research area → project → article → immutable released version. New analysis becomes a new revision, not a silent replacement. The existing Library, Workspace, Workbench, Lab and Site Intelligence services remain authoritative for their original data and permission scopes.

## Current delivery limits

This is a read-only development foundation. Protected editing, persistent PostgreSQL state, real research migration, figure renderers, cross-system adapters, production-host deployment and browser acceptance have not yet been implemented.
